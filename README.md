# Bizzrow

> A premium AI-powered business operating system for retailers and wholesalers.

Bizzrow is a mobile-first, WhatsApp-integrated, AI-assisted SaaS that helps businesses manage products, customer ledgers, sales, PDF invoicing, and communications — without feeling like ERP software.

> **Lineage:** originally **SmartVyapaar**, then **Thybizz**, now permanently **Bizzrow**. Only visible branding changed — the MongoDB database name stays `smartvyapaar` and all collection/route names are unchanged for backward compatibility with existing production data.

## Sprint 1 (Bizzrow) highlights

- **Forgot / reset password** — secure SHA-256-hashed, one-time, 1-hour-expiry tokens; email via SMTP with a graceful dev fallback. New pages `/forgot-password` and `/reset-password`.
- **Search everywhere** — debounced, server-backed product (name / SKU / category) and customer (name / phone) search inside the Create Sale flow. Reusable `server/utils/search.js` + client `useDebounce` hook.
- **Sales filters** — date presets (today / yesterday / this week / this month / last month / custom), payment status, customer search, and amount/date sorting.
- **Customer ledger statement** — opening / running / closing balance with date ranges and **PDF export**; structured so WhatsApp sharing can be added later.

See **`CHANGELOG.md`** for the full Sprint 1 changelog, new env vars, schema notes, testing checklist, and deployment steps.

## Real WhatsApp + PDF invoices

- **Live Meta WhatsApp Cloud API** — `server/services/whatsappService.js` sends real text, image, document, and template messages via the Graph API. Every send is logged to `WhatsAppLog` with the provider message id or a captured error. Sends never throw, so sale recording is never blocked.
- **PDF invoices** — `server/services/pdfService.js` (pdfkit) renders a branded invoice with your logo, full line items, payment breakdown, and "Generated by Bizzrow". Download from any sale, or send it on WhatsApp as a document.

## What's new in V2

- **Premium dark theme** (default) with a light toggle. Theme persists to `localStorage` and writes through to the user's profile. Built on Tailwind class dark-mode + CSS-variable semantic tokens.
- **Business Health Score** — a flagship 0-100 score computed by a deterministic engine (`server/services/healthService.js`) from six weighted sub-scores (Inventory, Cash Flow, Payment, Sales, Product Performance, Customer). The AI layer writes the Strengths / Risks / Opportunities narrative on top. Shown as a circular gauge on the dashboard.
- **Business Profile** — upload a business logo (becomes the app's primary identity), owner name, address, GST, UPI ID, and UPI QR.
- **Retail workflow depth in Sales** — Existing / New / Walk-in customer types, create-a-customer-inside-the-sale, and **split payments** (cash + UPI + bank, auto-summed) with partial-payment due tracking. Walk-ins create no ledger entry and must be fully paid.
- **Executive dashboard** — KPI row (revenue, collection, pending, inventory value), health + AI, collection analytics (today's breakdown + month donut), inventory intelligence (fast / slow / low / dead), and recent activity.
- **AI repositioned** as a Business Intelligence Engine (not a chatbot).

## Quick start

### 1. Prerequisites

- Node.js 18+
- MongoDB running locally (`mongodb://127.0.0.1:27017/smartvyapaar`) or a hosted URI
- A Google Gemini API key (get one free at https://aistudio.google.com/apikey)
- (Optional, for live messaging) Meta WhatsApp Cloud API credentials — see https://developers.facebook.com → your app → WhatsApp → API setup

### 2. Server

```bash
cd server
cp .env.example .env
# edit .env and set MONGO_URI, JWT_SECRET, GEMINI_API_KEY
npm install
npm run dev
```

Server runs on `http://localhost:5000`.

### 3. Client

```bash
cd client
cp .env.example .env
# default VITE_API_URL=http://localhost:5000/api is fine for local dev
npm install
npm run dev
```

Client runs on `http://localhost:5173`.

### 4. First-time setup

1. Open the client URL.
2. Register a new account (this becomes the business owner).
3. Add a few products, a couple of customers, then record a sale.
4. Click **Refresh insights** on the dashboard to generate AI summaries from your real data.

## WhatsApp (live Meta Cloud API)

`server/services/whatsappService.js` calls the real Graph API. Set `WHATSAPP_ACCESS_TOKEN` and `WHATSAPP_PHONE_NUMBER_ID` in `server/.env`, restart, then verify on the **WhatsApp** page → **Send test message** (or `POST /api/whatsapp/test`).

Functions (all log to `WhatsAppLog`, all return `{ status: "sent" | "failed", messageId?, error? }`, none throw):

- `sendText`, `sendMedia` (image by link), `sendDocument` (by link or uploaded media id), `sendTemplate`
- `uploadMedia` — multipart upload of a buffer (e.g. a PDF) → returns a Meta media id
- `sendInvoice` (branded summary + optional PDF document), `sendReminder`, `sendBroadcast` (supports a `{name}` merge token)

Getting credentials: https://developers.facebook.com → your app → **WhatsApp → API setup**. Use a System User permanent token for production. Recipients must have opted in (or be test numbers) per Meta policy.

> Note: free-form text/document sends work within the 24-hour customer service window. Outside that window Meta requires approved **message templates** — use `sendTemplate` with a template you've approved in WhatsApp Manager.

## PDF invoices

`server/services/pdfService.js` (pdfkit) builds a branded invoice: business logo + name + contact, invoice number/date, customer name + phone, line items, totals, **payment breakdown** (Cash/UPI/Bank), paid/due, and a "Generated by Bizzrow" footer.

- `GET /api/sales/:id/invoice/pdf` — streams a downloadable PDF (client downloads it as a blob, preserving JWT auth).
- `POST /api/sales/:id/invoice/whatsapp` — regenerates the PDF, uploads it to Meta, and sends the summary + PDF document to the customer.

From the **Sales** page, each row has **Download PDF** and **Resend on WhatsApp**; opening a sale also offers **Send reminder** when a balance is due.

> pdfkit's built-in font has no ₹ glyph, so the PDF uses an ASCII `Rs.` prefix for amounts (WhatsApp/HTML still use ₹).

## AI insights

Insights are generated on demand by clicking **Refresh** on the dashboard or AI page. Results are stored in the `AIInsight` collection (tagged by `kind`) so subsequent dashboard loads do not re-prompt Gemini. The full prompt templates live in `server/services/aiService.js`.

## Business Health Score

- `GET /api/business-health/score` — deterministic score + sub-scores + metrics + any cached AI narrative (always fresh, no Gemini call).
- `POST /api/business-health/refresh` — recomputes and (re)generates the AI Strengths / Risks / Opportunities narrative, caching it in `AIInsight`.

The scoring logic and tunable weights live in `server/services/healthService.js`. It's pure and unit-testable — same data in, same score out.

## Key V2 API additions

| Method | Path | Purpose |
| --- | --- | --- |

## Production notes

- Set strong `JWT_SECRET`, restrict `CLIENT_ORIGIN`, and run MongoDB with auth enabled
- Add reverse proxy / TLS (nginx, Caddy) in front of the Express server
- Optional: replace base64 product images with S3 + signed URLs once you outgrow MongoDB document size limits
- PDF invoices are generated server-side with `pdfkit`; for high volume, consider caching generated PDFs or moving generation to a worker
- For WhatsApp at scale, use a System User permanent token and pre-approved message templates; respect Meta's 24-hour customer-service window
